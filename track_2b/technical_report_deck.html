1 — Problem
and users

A procurement review compares the same commercial terms across documents written at different times by different functions: a master agreement, the buyer's accounts-payable policy, and the invoices raised under them. The disagreement that matters is rarely a missing number — it is the same term stated two ways, and finding it means reading the same clause in three places.

Why a model answer is not enough

Large language models are good at the reading and the judging. They are unreliable as the source. A model asked to quote a document will produce a quotation that reads plausibly and does not appear in the document, and a reviewer has no cheap way to tell the difference. That failure mode converts a slow task into a slow task plus a verification task.

Sovra Verify separates the two roles. The model reads and judges; the evidence comes from canonical extracted text that the model cannot write to. The output is a set of potential inconsistencies, each carrying the passage, page and character offsets it rests on, for a human to review.

Who this is for, and what it is not

The primary user is a procurement or finance reviewer performing a consistency check before an approval. The system is not a lawyer, not a compliance authority and not an approver. It reports inconsistencies in the corpus it was given; it does not check external truth, does not decide which document governs, and produces no legally operative result. Every screen that can produce a finding states this next to the controls that produce it.

Scope. Text-native PDF and UTF-8 TXT, one project, up to ten documents, 10 MB per file, with an explicit extracted-text budget. Oversized, encrypted and unsupported files are rejected with a reason; a scanned PDF reports “OCR not implemented” rather than yielding empty evidence. DOCX, OCR, authentication, integrations and multi-project support are out of scope for this prototype.

2Architecture and the role of Apertus
Stack

A Python 3.12 FastAPI backend with a React and TypeScript dashboard built by Vite and served by the backend. PyMuPDF extracts text-native PDFs; SQLite stores documents, passages, claims, analyses, findings, provider runs and review history.

Reasoning
layer

Apertus is the reasoning layer. swiss-ai/Apertus-v1.5-70B, served by CSCS at https://api.inference.cscs.ch/v1 over OpenAI-compatible Chat Completions, does exactly two jobs:

  1. Claim identification. For each batch of passages it returns typed claims — subject, predicate, value, unit, scope, effective date — with a nominated passage id and character offsets.
  2. Scoped comparison. For one bounded claim pair it returns a relation (consistent, potential_conflict, insufficient_evidence, unrelated), a short reasoning sentence, cited spans and explicit limitations.

Nothing else is delegated

The model never authors a quote, never chooses a provider or a URL, never selects a file path, and never decides a relation for a pair it was not shown. Constrained decoding, the Responses API, tool calls and embedding endpoints are treated as unverified capabilities and are not relied on; output is validated application-side with Pydantic.

Provider policy

CSCS is primary. The Hugging Face router is a backup that is off by default, because it cannot serve the default model: its only Apertus entry is swiss-ai/Apertus-8B-Instruct-2509, and the Apertus-v1.5-70B mapping reports status: "error".

The 70B model is never silently swapped for an 8B model: the 8B path needs SOVRA_ALLOW_OPTIONAL_8B=1, and switching providers needs SOVRA_BACKUP_ENABLED=1 and SOVRA_ALLOW_BACKUP_FALLBACK=1. A change is recorded on the run as is_backup = true with downgraded_from set.

Failure is a first-class outcome

Every call writes a ProviderRun with provider, model, mode, latency, token usage, error class, HTTP status and validation errors. A run whose comparison calls all failed finishes as failed, not as a clean empty finding list, and says so in the output and the export. Partial runs are labelled partial with the failures attached.

3The evidence model

The evidence model is the core contribution, and it is enforced by construction rather than by prompting.

Authority

Canonical text is the authority

Each document's extracted text is stored once, and (start_offset, end_offset) index into it. Critically, offsets are per document: every span resolves against the canonical text of the document it came from. An early implementation joined canonical text per passage across the whole corpus, so a span from the second document was sliced out of the first document's text. A test that asserts every produced citation equals its own document's canonical slice caught it before any result was reported.

Derivation

Quotes are derived, never authored

The model nominates a passage id and an offset pair. A quote string supplied by the model is discarded on sight; the quote is sliced from canonical text after validation: the passage exists, the offsets are ordered and in range, the span overlaps the passage it claims to come from, the derived quote is at least eight non-whitespace characters, and it is a substring of that passage. There is no code path by which model-written text becomes displayed evidence.

Rejection

Unresolvable evidence is rejected, not softened

A potential_conflict with no validated citation is dropped, and the count of dropped conflicts is reported as a limitation. A claim the model attributes to a passage id that does not exist is stored as unresolved and is never paired.

Uncertainty

Uncertainty is labelled, not scored

Unknown dates and scopes stay unknown rather than being guessed. No calibrated confidence percentage is emitted, because the system is not separately calibrated; uncertainty is expressed as explicit limitation strings. Review states are pending confirmed for review dismissed — never “resolved” or “approved”.

Retrieval

Retrieval is bounded and its gaps are visible

Only cross-document claim pairs whose normalised predicate, unit, entity and effective date align become candidates. Pairs describing the same difference are deduplicated, so one conflict is reported once. Coverage statistics — pairs considered, after deduplication, compared, dropped by cap, and the top reasons pairs were skipped — are stored on the analysis, so a retrieval miss cannot hide. A differing known effective date is treated as an explanation rather than a conflict, and the number of pairs skipped for that reason is reported so the reader can audit the choice.

These statements are verified where a reviewer reads them: make ui-check drives the running interface in a headless browser and asserts that a compared pair's judged outcome is stated, that a completed run reporting nothing says so, and that no footer marker appears in the rendered text or the DOM. Over the demo corpus that run compared 11 pairs: “11 compared pair(s) were judged: 10 potential conflict, 1 consistent”.

Untrusted
input

Imported documents are data

Prompt templates state that passage text is untrusted user data which cannot alter the task, the output format, the provider or the tools. No tool, network request, code execution or file access is ever derived from document text, and adversarial evaluation rows carrying injection payloads are treated as data under test.

Abstention, not error, dominates the count

Eleven cases were never compared, because the candidate filter did not consider the pair alignable, and four of those produced only one claim. Abstaining is safe — no unsupported claim reaches a reviewer — but it is not useful, and it is the largest single component of the error.

The single accuracy figure hides two different failures, so the evaluation reports them separately: 14 of the 25 cases ever reached the model. Of the 10 cases whose expected relation is a negative (unrelated or insufficient_evidence), 8 produced no inconsistency — the absence of a false alarm, not evidence of correctness.

The citation guarantee held

Every conflict the system reported carried a resolved span, and the separate end-to-end demo run over four documents produced 25 claims, 10 compared pairs and zero citations that did not equal an exact slice of their own document's canonical text. Tokens per case: mean 1,502.

What was
tested

The five false positives are all the model's own judgement, and this was established by experiment rather than assumed. An earlier revision of this report attributed the valid_exception errors to the exception clause being dropped before the comparison. That was wrong. The comparison prompt carries both claim passages in full, and the model cited the exception sentence as its own evidence before judging against it: for eval-018 the span it quoted reads “as an exception to Policy 4.1”, and its reasoning still called the values incompatible.

A prompt revision that also placed the surrounding statements of each claim's own document in front of the model, with an instruction to extract every distinct statement including stated exceptions, was measured against the same frozen corpus: 41 calls, 0 failed, and every case landed on the same side as before. The changes are kept because a model should see the document it is judging, not because they raised the score. This evaluation is small, synthetic and single-run; it does not establish real-world performance.

5Deployment, cost and security
Verified
mode

A local application calling CSCS-hosted inference

That is external-network inference. A local web app calling CSCS is not air-gapped, and Swiss inference residency does not establish residency of the whole application — the database, stored originals, exports and logs remain the operator's responsibility. CSCS documentation states that prompts and responses are not recorded by CSCS; that covers the inference call, not the application.

Not claimed

On-premise, full Swiss-cloud and air-gapped deployments are not claimed. A local OpenAI-compatible Apertus adapter exists but has never been pointed at real on-premise hardware, and no no-network verification was performed.

Cost

Costs are bounded, and no dollar figure is reported

No verified price list was available, so a cost per case would be an invented number. The account's $10 Hugging Face credit is user-reported and was not measured, and no paid dedicated endpoint was deployed. Work per analysis is bounded by max_output_tokens, a comparison cap, a chunk cap and a total extracted-text budget; retries are capped at two with backoff and only for transient errors.

Credentials

How they are read

From the process environment first and ~/.hermes/.env second, with only named keys extracted, never shell-sourced, never copied into the repository or an image layer, and masked in every log, argument and diagnostic.

How they travel

The Docker launcher passes the two application variables into the container by name, so no secret travels through a file or an argument, and compose.yaml has no env_file because that would leak every unrelated secret in the file. Judges supply their own credentials; no developer key ships with the submission.

Residual
risks

No API authentication exists. This is a single-user local prototype and must not be exposed to a network. Real sensitive documents should not be sent to any provider without authorisation and a data review.

Release
gates

6Limitations and next work
The honest
headline

Accuracy is not sufficient to trust the tool. 0.36 on a 25-case corpus is a weak result and is reported as measured.

Next work

The next work is the bottleneck the evaluation found, not new features.

  1. Candidate coverage. Abstention dominates the error. The pairing filter needs to over-generate candidates and let the model abstain, rather than under-generate and never ask.
  2. Surface abstention. “Considered and not reported” should be a visible state, so an empty result is distinguishable from a pair that was never compared. Today the metric records a miss where the interface arguably did the right thing.
  3. Same-document context. Exception and date-change false positives need the clause that modifies a term, which usually sits in the same document as the term.
  4. Real, reviewed data. An authorised deidentified historical corpus reviewed by a consenting domain expert, measuring false positives and omissions against that reviewer's judgement rather than against our own labels. No customer, ROI or deployment claim exists today and none should be made until such a review happens.
  5. DOCX and OCR, after a licensing review, and a tested on-premise or air-gapped Apertus deployment, which is currently an untested adapter.
Deliberately
not claimed

Air-gapped operation · production readiness · legal or compliance conclusions · automated policy changes · dollar cost · customer adoption · accuracy on real documents.
